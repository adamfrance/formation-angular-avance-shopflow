Les bases d'Angular, pour suivre Angular avancé

Les notions dont ShopFlow se sert, chacune avec une image de tous les jours, un exemple court à copier et ce qu'il affiche.

Tous les exemples ont été exécutés le 24/11/2026 dans un projet neuf créé par ng new, en Angular 22.3.0, la dernière version. ShopFlow est en Angular 22.2.7 : les bases sont les mêmes. Les exemples se copient avec le bouton « Copier ».

0

Mode d'emploi

Cette page reprend les bases d'Angular dont la formation se sert, pour qui n'a jamais fait d'Angular ou n'en a pas fait depuis longtemps. Chaque partie part d'une image de tous les jours, donne un exemple court à copier, et dit ce qu'il affiche.

Ce qu'il faut savoir avant :

  • HTML et CSS : balises, attributs, classes ;
  • JavaScript : variables (const, let), fonctions et fonctions fléchées ((x) => x + 1), tableaux (map, filter, find), objets, import et export ;
  • le terminal : se placer dans un dossier (cd), lancer une commande, l'arrêter avec Ctrl+C.

Le temps : environ trois heures pour tout lire et essayer chaque exemple. Si le temps manque, les parties 1 à 11 suffisent pour lire le code de ShopFlow ; les parties 12 à 16 préparent les jours 2 et 3.

Créer le bac à sable

Un projet à part, pour essayer les exemples sans toucher à ShopFlow. Dossier : celui où l'on range ses projets (sous Windows, dans Git Bash).

npx demande d'abord la permission de télécharger Angular CLI : répondre y. L'installation prend une à trois minutes. --defaults accepte les réponses par défaut (CSS, pas de rendu côté serveur) ; --skip-git évite de créer un dépôt Git. Ouvrir http://localhost:4200 : la page d'accueil d'Angular s'affiche (« Hello, bac-a-sable »). Le serveur reste lancé et recharge la page à chaque enregistrement ; Ctrl+C l'arrête.

Préparer le projet

Ouvrir le dossier bac-a-sable dans VS Code, créer le dossier src/app/exemples/ (chaque exemple y prend place, sous le nom écrit au-dessus de son code), puis remplacer src/app/app.config.ts : il ajoute les appels HTTP et les formats français (prix, dates) dont se servent les exemples.

1

Angular en deux minutes

L'image

Sur un site classique, chaque clic redemande une page entière au serveur, comme si l'on sortait d'un magasin pour entrer dans le suivant. Une application Angular est un seul grand magasin : on change de rayon sans ressortir, et seules les marchandises (les données) arrivent de l'entrepôt (le serveur, par son API).

Angular est un framework de Google pour construire ces applications d'une seule page (SPA, single-page application). Il a remplacé AngularJS en 2016, et une version majeure sort tous les six mois. Une application Angular est un arbre de composants : chacun est un morceau d'écran (un en-tête, une carte produit, une page), avec son HTML et son code.

Pièce Rôle Partie
Composant Un morceau d'écran : son template (HTML) et sa classe (TypeScript) 3
Signal Une valeur qui change et qui prévient l'affichage 4
Template Le HTML du composant, relié à ses données 5 et 7
Pipe La mise en forme d'une valeur dans le template (prix, date) 6
Service Le code partagé : données, appels à l'API, état commun 9
Routeur Une adresse (/panier), une page 11

Ce que crée ng new, et le rôle de chaque fichier au démarrage :

Fichier Rôle
src/index.html La seule page HTML ; elle contient la balise <app-root></app-root>
src/main.ts Démarre Angular : affiche le composant App à la place de <app-root>
src/app/app.ts Le composant racine, qui contient tous les autres
src/app/app.config.ts Ce que l'application met à disposition : routeur, appels HTTP, langue
src/app/app.routes.ts La liste des adresses et de leurs pages
angular.json, package.json La configuration du projet et ses dépendances
Dans ShopFlow

La même structure, avec en plus, dans src/app/, les dossiers models/ (les types des données), services/ (l'API et l'état partagé), layout/ (l'en-tête), pages/ (une page par dossier) et admin/ (l'administration).

Le minimum de TypeScript

L'image

Les types sont les étiquettes d'un déménagement : « livres », « vaisselle ». Le carton ne change pas de contenu, mais on sait tout de suite ce qu'il contient, et une erreur se voit avant de l'ouvrir.

TypeScript, c'est JavaScript avec des types. Le navigateur n'exécute que du JavaScript : Angular CLI traduit le TypeScript à chaque construction et signale les erreurs de type avant même qu'on ouvre la page.

Créer ce fichier : les exemples suivants s'en servent.

Écriture Sens
id: number id contient un nombre (string : un texte ; boolean : vrai ou faux)
interface Produit { … } La forme d'un objet ; elle sert à vérifier le code et disparaît à l'exécution
remise?: number Une propriété facultative
'en-attente' | 'payee' Une valeur parmi une liste fermée
Produit[] Un tableau de produits
produit.remise ?? 0 La valeur de gauche, ou 0 si elle manque (null ou undefined)
(q) => q + 1 Une fonction fléchée : elle reçoit q et renvoie q + 1
export et import { Produit } from './produit' Rendre visible hors du fichier, puis s'en servir ailleurs
signal<string | null>(null) Les chevrons précisent le type de ce que contiendra le signal

Les composants et les services sont des classes (class Compteur { … }). Trois mots y reviennent sans cesse :

  • readonly : la propriété ne sera jamais remplacée par une autre valeur ;
  • private : utilisable seulement dans la classe ; protected : dans la classe et dans son template ;
  • @Component(…), @Service() : des décorateurs, des étiquettes posées sur une classe pour dire à Angular ce qu'elle est.
À retenir
  • Les types n'existent qu'à l'écriture : ils évitent des erreurs, ils ne changent rien à l'exécution.
  • Une interface décrit des données ; une class contient du code.
Dans ShopFlow

src/app/models/ contient les interfaces des données de l'API (Product, CartLine, User, Order) et la fonction prixRemise().

Le composant

L'image

Un composant est une pièce de Lego : une forme (le template), une couleur (les styles) et une fiche technique (la classe). On assemble les pièces pour construire l'écran, et la même pièce sert autant de fois qu'on veut.

Un composant est une classe décorée par @Component. Le décorateur dit trois choses :

  • selector : la balise qui affiche le composant, ici <app-bonjour /> ;
  • template : son HTML ; {{ prenom }} y affiche la propriété prenom de la classe (on parle d'interpolation) ;
  • styles : son CSS, qui ne s'applique qu'à lui : le h1 rouge d'ici ne touche pas aux h1 des autres composants.

« Bonjour Léa ! » en rouge, puis « Bienvenue dans la formation Angular avancé. »

Les exemples de cette page tiennent chacun dans un seul fichier ; ShopFlow, lui, range le template à part (templateUrl: './product-card.html').

À retenir
  • Un composant, c'est une classe et un @Component : sa balise, son template, ses styles.
  • Ce que le template utilise (un autre composant, un pipe) se déclare dans imports.
  • Les fichiers s'appellent carte.ts et les classes Carte ; on trouve encore carte.component.ts et CarteComponent dans le code ancien.

4

Les signaux

L'image

Un signal est le tableau des départs d'une gare : quand un horaire change, tous ceux qui le regardent voient la nouvelle valeur, sans retourner la demander au guichet.

Une donnée qui change pendant que l'écran est affiché (une quantité, un filtre, un panier) se range dans un signal. Angular sait alors quels affichages en dépendent, et les met à jour.

Écriture Sens
signal(1) Crée un signal qui vaut 1
quantite() Lit la valeur : un signal se lit avec des parenthèses
quantite.set(1) Remplace la valeur
quantite.update((q) => q + 1) Calcule la nouvelle valeur à partir de l'ancienne
computed(() => …) Un signal calculé à partir d'autres, recalculé seulement quand l'un d'eux change
effect(() => …) Une action relancée à chaque changement des signaux qu'elle lit (journal, sauvegarde) ; on en a rarement besoin
Ce qu'on voit

« 1 × 12 € = 12 € ». Deux clics sur « +1 » : « 3 × 12 € = 36 € ». « Remettre à 1 » : « 1 × 12 € = 12 € ». Dans la console du navigateur (F12) : « Quantité : 1 », « Quantité : 2 », « Quantité : 3 », puis « Quantité : 1 ».

Piège

Oublier les parenthèses. {{ quantite }} affiche « [Signal (quantite): 1] » au lieu de 1, et la construction prévient : « NG8109: quantite is a function and should be invoked: quantite() ». On écrit {{ quantite() }}.

À retenir
  • Une donnée affichée qui change : un signal.
  • On lit avec (), on écrit avec set() ou update().
  • Ce qui se déduit d'autres données s'écrit en computed(), jamais en copie mise à jour à la main.
Dans ShopFlow

Pas encore de signaux : l'état du panier et de la session y est rangé dans des BehaviorSubject (partie 10). Le panier passe en signaux au jour 2.

Le template et les liaisons

L'image

Le template est un formulaire préimprimé : certaines cases se remplissent avec les données du composant, d'autres déclenchent une action quand on les touche.

Écriture Sens Dans l'exemple
{{ expression }} Affiche une valeur dans le texte {{ titre }}
[propriété]="expression" Donne une valeur à une propriété d'un élément [src]="image"
[class.nom]="condition" Ajoute la classe CSS tant que la condition est vraie [class.promo]="enPromo()"
(événement)="instruction" Exécute du code quand l'événement arrive (click)="enPromo.set(!enPromo())"
(keyup.enter) Le même, pour une seule touche la recherche part à l'appui sur Entrée
#nom Nomme un élément, pour s'en servir ailleurs dans le template #champ, puis champ.value

Les crochets vont du composant vers la page, les parenthèses de la page vers le composant. Entre crochets, on écrit une expression : [alt]="titre" donne le contenu de la propriété titre, alors que alt="titre" écrit le mot « titre ».

Ce qu'on voit

L'image du mascara (téléchargée depuis DummyJSON), « Mascara », puis le bouton « Promotion : non ». Un clic sur le bouton : « Mascara » passe en rouge et en gras, le bouton affiche « Promotion : oui ». Taper « rouge » puis Entrée : « Recherche : rouge ».

À retenir
  • {{ }} et [ ] : du composant vers la page ; ( ) : de la page vers le composant.
  • Dans un (click), une instruction courte ; au-delà, une méthode ((click)="ajouter()"), plus lisible et testable.
Dans ShopFlow

pages/catalogue/product-card.html : [src]="p.thumbnail", [routerLink], (click)="ajouter()".

Les pipes

L'image

Un pipe est un papier cadeau : le cadeau (la donnée) ne change pas, seule sa présentation change.

Un pipe s'écrit après une barre verticale : valeur | nom: paramètre. Les pipes s'enchaînent : prix | remise: 10 | currency: 'EUR' applique la remise, puis met le résultat en forme. Ceux d'Angular (currency, date, uppercase, number, percent…) s'importent depuis @angular/common ; un pipe à soi est une classe décorée par @Pipe, avec une méthode transform.

Ce qu'on voit

« MASCARA », « Prix : 9,99 € », « Prix remisé : 8,99 € », « Livraison le 27 novembre 2026 ». Les formats français viennent de deux lignes de app.config.ts : registerLocaleData(localeFr) et LOCALE_ID.

À retenir
  • Un pipe met en forme pour l'affichage ; il ne modifie pas la donnée.
  • currency attend le code de la devise : currency: 'EUR'.
  • Un pipe se déclare dans imports, comme un composant.
Dans ShopFlow

currency: 'EUR' sur toutes les pages (carte, fiche, panier, commande) et number: '1.1-1' pour la note des produits.

Conditions et listes

L'image

Le template a ses aiguillages : @if choisit une voie selon une condition, @for fait défiler une liste comme le tapis d'une caisse, un article après l'autre.

Écriture Sens
@if (condition) { … } @else { … } Affiche un bloc ou l'autre
@for (produit of liste; track produit.id) { … } Répète le bloc pour chaque élément
@empty { … } Ce qu'affiche @for quand la liste est vide
@let nombre = …; Donne un nom à une valeur, dans le template
@switch (valeur) { @case (…) { … } @default { … } } Choisit un bloc selon une valeur

track est obligatoire : c'est le numéro de série de chaque élément. Quand la liste change, Angular reconnaît les éléments qui restent et ne redessine que ceux qui changent. On suit un identifiant unique (produit.id) ; avec track $index (la position), un élément qui change de place n'est plus reconnu.

Ce qu'on voit

Les trois produits, chacun « disponible » ou « épuisé », puis « 3 produit(s) affiché(s) » et « Commande payée ». Case « En stock seulement » cochée : le rouge à lèvres disparaît, « 2 produit(s) affiché(s) ».

À retenir
  • @if, @for et @switch sont l'écriture d'aujourd'hui ; *ngIf et *ngFor sont l'ancienne (partie 16).
  • Toujours un track sur un identifiant.
Dans ShopFlow

pages/catalogue/catalogue.html affiche les produits avec @for (…; track $index) : un des défauts relevés pendant la visite de ShopFlow.

Faire communiquer deux composants

L'image

Le parent tend un dossier à l'enfant : c'est l'entrée (input). L'enfant lève la main pour prévenir le parent : c'est la sortie (output). L'enfant ne sait pas qui est son parent, si bien qu'il peut servir partout.

L'enfant, une carte qui reçoit un produit et prévient quand on clique sur « Ajouter » :

Le parent, qui affiche une carte par produit et réagit à ses clics :

Côté Écriture Sens
Enfant produit = input.required<Produit>() Une entrée obligatoire ; input(valeur) pour une entrée facultative, avec sa valeur par défaut
Enfant produit() Lit l'entrée : c'est un signal
Enfant ajout = output<Produit>(), puis ajout.emit(p) Une sortie, puis son envoi
Parent [produit]="produit" Donne la valeur de l'entrée
Parent (ajout)="ajouter($event)" Réagit à la sortie ; $event est la valeur envoyée
Ce qu'on voit

Trois cartes : « Mascara 8,99 € », « Rouge à lèvres 12,99 € » (bouton grisé : épuisé) et « Parfum 39,99 € ». Un clic sur « Ajouter » du parfum : « Dernier ajout : Parfum ».

À retenir
  • Du parent vers l'enfant : input() ; de l'enfant vers le parent : output().
  • Une entrée se lit comme un signal (produit()) et se combine dans un computed().
Dans ShopFlow

pages/catalogue/product-card.ts reçoit son produit par input.required<Product>() ; le catalogue l'affiche avec <app-product-card [product]="p" />.

Les services et l'injection de dépendances

L'image

Un service est le guichet unique d'une mairie : tous les habitants (les composants) s'adressent au même guichet, qui garde les dossiers. L'injection de dépendances, c'est l'accueil : on demande le guichet et l'on vous y conduit ; personne ne construit son propre guichet.

@Service(), apparu avec Angular 22, déclare un service dont Angular crée une seule instance, partagée par toute l'application, la première fois qu'on la demande. inject(PanierService) demande cette instance. L'en-tête et le magasin reçoivent le même panier : ce que l'un ajoute, l'autre l'affiche.

Ce qu'on voit

« Panier : 0 article(s), 0,00 € ». Un clic sur « Ajouter Mascara », puis sur « Ajouter Parfum » : « Panier : 2 article(s), 59,98 € ».

Pièges
  • new PanierService() crée un second panier, que personne d'autre ne voit : on demande toujours un service avec inject().
  • Un service @Service() reçoit lui aussi ses propres services par inject(). Par le constructeur, la construction échoue : « NG2028: @Service class cannot use constructor dependency injection. Use the inject function instead. »

Avant Angular 22, on écrivait @Injectable({ providedIn: 'root' }) : cette écriture fonctionne toujours, et c'est elle qu'on trouve dans la plupart des tutoriels (partie 16). Pour une instance par composant (chaque liste avec son propre filtre) : @Service({ autoProvided: false }), puis providers: [FiltreService] dans le composant.

À retenir
  • Ce qui est partagé (données, appels à l'API, état commun) va dans un service.
  • On ne fait jamais new sur un service : on le demande avec inject().
Dans ShopFlow

services/cart-service.ts (le panier), services/auth-service.ts (la session), services/product-service.ts (les produits).

Les observables et HttpClient

L'image

Un observable est un abonnement à un journal : tant qu'on ne s'abonne pas, rien n'arrive ; une fois abonné, chaque numéro arrive quand il est prêt. Une requête HTTP est un abonnement qui ne livre qu'un numéro : la réponse du serveur.

Le service prépare la requête :

Le composant s'y abonne, de deux façons :

Écriture Sens
http.get<T>(adresse) Prépare une requête GET ; renvoie un Observable<T>
.pipe(map(…)) Transforme ce qui arrive avant de le livrer
produits$ | async S'abonne dans le template, affiche chaque valeur, se désabonne quand le composant disparaît
@if (produits$ | async; as produits) Nomme la valeur reçue ; affiche le bloc @else tant qu'elle n'est pas arrivée
toSignal(observable, { initialValue: [] }) S'abonne et range chaque valeur dans un signal

HttpClient ne fonctionne que si provideHttpClient() figure dans app.config.ts, ce qui est fait. RxJS, la bibliothèque des observables, fournit des dizaines d'opérateurs (map, filter, switchMap, debounceTime…) ; le jour 2 en utilise plusieurs. Pour les voir en schémas animés : RxMarbles.

Ce qu'on voit

« Chargement… », puis cinq produits de DummyJSON : « Essence Mascara Lash Princess : 9,99 € », « Eyeshadow Palette with Mirror : 19,99 € »… Sous « Avec toSignal » : « 5 produit(s) reçu(s) ». Dans l'onglet Réseau (F12) : deux requêtes products?limit=5…, une par abonnement.

Piège

Chaque abonnement relance la requête : ici, | async et toSignal en envoient deux. Dans ShopFlow, c'est la ligne 5 du cahier des charges (le catalogue demandé trois fois), corrigée au jour 2.

À retenir
  • Une requête ne part qu'à l'abonnement, et chaque abonnement en envoie une.
  • Dans un template : | async ou toSignal(), qui se désabonnent tout seuls.
Dans ShopFlow

services/product-service.ts (getAll(), getById()), et | async dans presque tous les templates. Le panier y est un BehaviorSubject : un observable qui garde sa dernière valeur.

Le routage

L'image

Le routeur est le plan d'un centre commercial : à chaque adresse correspond une boutique. <router-outlet /> est l'emplacement où s'installe la boutique de l'adresse courante ; le reste (en-tête, menu) ne bouge pas.

Créer routage.ts, puis remplacer src/app/app.routes.ts :

Écriture Sens
{ path: 'produits', component: ListeProduits } L'adresse /produits affiche ListeProduits
'produits/:id' :id est une partie variable : /produits/3
redirectTo et pathMatch: 'full' L'adresse vide renvoie vers /produits
'**' Toute autre adresse ; toujours en dernier, car les routes sont lues dans l'ordre
[routerLink]="['/produits', p.id]" Un lien vers /produits/3, sans recharger la page
inject(ActivatedRoute).paramMap Les paramètres de l'adresse, sous forme d'observable
Ce qu'on voit

Sous l'exemple affiché par app.ts, la liste « Mascara, Rouge à lèvres, Parfum » (l'adresse / est devenue /produits). Un clic sur « Parfum » : l'adresse devient /produits/3, la page affiche « Parfum » et « Produit n° 3 », sans rechargement. /produits/99 : « Produit introuvable ». Une adresse inconnue ramène à /produits.

paramMap est un observable, car l'identifiant peut changer sans que la page soit recréée (un lien d'une fiche vers une autre). Le chargement d'une page à la demande (loadComponent) et la protection des pages (les guards) sont au programme du jour 2.

À retenir
  • Une route : une adresse et un composant ; ** en dernier.
  • Un lien interne : routerLink, jamais href, qui rechargerait toute l'application.
Dans ShopFlow

app.routes.ts (catalogue, fiche, panier, commande, connexion, et l'administration avec ses routes enfants) ; pages/product-detail/product-detail.ts lit l'identifiant avec paramMap.

Les formulaires réactifs

L'image

Un dossier d'inscription vérifié à l'accueil : chaque case a ses règles, et le dossier n'est accepté que lorsqu'elles sont toutes respectées.

Écriture Sens
inject(NonNullableFormBuilder).group({ … }) Construit le formulaire : un champ par clé, avec sa valeur de départ et ses règles
Validators.required, minLength(2), email Les règles ; il en existe d'autres (min, max, pattern)
[formGroup]="formulaire", formControlName="nom" Relient le formulaire HTML à celui du composant
(ngSubmit)="envoyer()" L'envoi du formulaire
controls.nom.invalid, controls.nom.touched Le champ ne respecte pas ses règles ; l'utilisateur l'a quitté
markAllAsTouched() Marque tous les champs comme touchés, pour afficher tous les messages
getRawValue() Les valeurs saisies, typées

ReactiveFormsModule, dans imports, apporte [formGroup] et formControlName. Les formulaires pilotés par le template (ngModel) existent aussi, pour un ou deux champs ; dès qu'il y a des règles, on préfère les formulaires réactifs, dont les règles sont écrites dans le code et se testent.

Ce qu'on voit

Un clic sur « S'inscrire » sans rien remplir : « Le nom est obligatoire (2 caractères au moins). » et « Adresse e-mail invalide. ». Avec « Léa » et « lea@exemple.fr » : « Bienvenue Léa ! ».

À retenir
  • Les règles dans le composant, les messages dans le template.
  • Une erreur ne s'affiche que sur un champ touché ; sinon, le formulaire serait rouge avant toute saisie.
Dans ShopFlow

La page de commande (pages/checkout/checkout.ts) accepte un envoi vide : c'est la ligne 8 du cahier des charges, corrigée au jour 3 avec un formulaire réactif.

13

Le cycle de vie

L'image

Un composant vit comme un employé saisonnier : on l'installe à son poste (ngOnInit), il travaille, et avant de partir il rend ses clés et éteint la lumière (ngOnDestroy).

Angular appelle ces méthodes au bon moment :

  • le constructeur : la classe est créée ; on y demande les services (inject()), rien de plus ;
  • ngOnInit() : le composant est prêt et ses entrées sont reçues ; on y lance le travail (un minuteur, un premier chargement) ;
  • ngOnDestroy() : le composant va disparaître (un @if devenu faux, un changement de page) ; on y arrête ce qui tournerait encore.
Ce qu'on voit

L'heure, mise à jour chaque seconde, et dans la console : « Horloge : ngOnInit ». Un clic sur « Masquer l'horloge » : l'horloge disparaît et la console affiche « Horloge : ngOnDestroy ».

Piège

Un minuteur ou un abonnement qu'on n'arrête pas continue de tourner après la disparition du composant, et un nouveau s'y ajoute à chaque affichage. C'est la ligne 6 du cahier des charges de ShopFlow (l'administration continue d'envoyer des requêtes une fois quittée), corrigée au jour 2.

Autres écritures qu'on rencontre : inject(DestroyRef).onDestroy(() => …), et, pour un observable, takeUntilDestroyed(), qui le désabonne à la destruction. Les autres méthodes du cycle de vie (ngOnChanges, ngAfterViewInit…) servent moins depuis les signaux : une valeur qui dépend d'une entrée s'écrit en computed().

À retenir
  • inject() à la création, le travail dans ngOnInit(), le ménage dans ngOnDestroy().
Dans ShopFlow

admin/live-orders.ts et pages/orders/orders.ts.

Quand l'affichage se met-il à jour ?

L'image

Angular ne surveille pas tout en permanence : il redessine un composant quand on le prévient, comme un livreur qui ne passe que si on l'appelle.

Un projet Angular 22 n'installe plus Zone.js, la bibliothèque qui, dans les anciennes versions, prévenait Angular après chaque clic, chaque minuteur et chaque réponse HTTP. Angular redessine maintenant un composant quand :

  • un signal lu par son template change ;
  • un événement de son template arrive ((click), (input)…) ;
  • une de ses entrées (input()) change ;
  • le pipe async reçoit une valeur.
Ce qu'on voit

Un clic sur « Lancer ». Au bout d'une seconde, la propriété ordinaire vaut « après » dans le code, mais l'écran affiche toujours « avant » : Angular n'a pas été prévenu. Au bout de trois secondes, le signal change : Angular redessine le composant, et les deux lignes affichent « après ».

À retenir
  • Une donnée qui change et qui s'affiche : un signal, ou un observable affiché avec | async.
  • Une propriété ordinaire modifiée dans un setTimeout ou un subscribe ne s'affiche pas tout de suite.
Dans ShopFlow

C'est le sujet du jour 2 (détection des changements, ChangeDetectorRef, signaux) ; Zone.js y est montré en captures.

Les tests

L'image

Un test est un contrôle qualité automatique : on décrit ce qu'on attend, et la machine le vérifie à chaque modification, sans oubli ni fatigue.

Un projet Angular 22 teste avec Vitest. Un fichier de test porte le nom du fichier testé, en .spec.ts.

describe regroupe les tests d'un élément, it décrit un comportement attendu, expect(…).toBe(…) le vérifie. Pour un composant, TestBed.createComponent() le crée hors de toute page, fixture.whenStable() attend qu'il soit affiché, et fixture.nativeElement donne son HTML. Sans --watch=false, Vitest reste ouvert et relance les tests à chaque enregistrement.

Ce qu'on voit

« Test Files 2 passed (2) » et « Tests 2 passed (2) ».

Dans ShopFlow

Pas encore de tests : ils arrivent au jour 3, avec la ligne 9 du cahier des charges (le même prix sur la carte et sur la fiche, vérifié par un test).
